# AnimePromptLoom

**Danbooru 태그 기반 2D 이미지 모델을 위한 로컬 프롬프트 작업 도구**입니다. ComfyUI와 별개로 실행하며, 한국어 장면 요청을 영문 묘사와 CSV 확인 태그로 변환합니다. 캐릭터·배경 설정과 최근 대화를 함께 전달하고, 프롬프트 지침은 `system_prompt.txt`에서 조정합니다.

**개발 단계입니다.** Ollama의 로컬/클라우드 대화 모델과 Gemini API를 지원합니다. 기존 기본 모드는 유지하며 확장 모드에는 별도 지침과 컨텍스트 옵션을 제공합니다. [Gemini 키 저장·GLM·확장 모드 사용 안내](FRONTIER.md). NAI 및 다른 2D 모델을 위한 출력 프리셋·문법 전환은 아직 구현되지 않았습니다. 이 저장소 등록은 개발 소스 관리용이며 릴리스나 배포 패키지가 아닙니다. 업로드 검토와 남은 조건은 [DEVELOPMENT_REVIEW.md](DEVELOPMENT_REVIEW.md)에 기록합니다.

## 실행

필요: Python 3.10 이상, 태그 CSV, Ollama의 대화 모델 또는 Gemini API 키. 외부 Python 패키지는 없습니다.

1. 최초 모델 설치: `ollama pull qwen3:8b`.
2. [CSV 준비 안내](data/SOURCE.md)에 따라 태그 CSV를 `data/danbooru_tags_classified.csv`에 둡니다. CSV와 모델 가중치는 저장소에 포함하지 않습니다.
3. `start.cmd` 더블 클릭. 또는 `python app.py --open --start-ollama`.
4. 브라우저에서 `http://127.0.0.1:8765`를 사용합니다.

Ollama가 꺼져 있으면 앱이 숨김 창으로 서버를 시작합니다. 자동 시작이 실패하면 별도 터미널에서 `ollama serve`를 실행하세요. 종료는 화면의 **앱 종료** 또는 Python 실행 창에서 Ctrl+C. 앱이 직접 시작한 Ollama 서버만 함께 종료하며 이미 사용 중이던 서버는 유지합니다.

## 컨텍스트 사용

- **대화 이름 / 새 대화**: 캐릭터·배경·기록을 대화별로 분리합니다.
- **캐릭터 추가**: 최대 12명의 특징과 이름 사용 방식을 각각 설정합니다.
- **구분용 이름**: `유나`처럼 요청에서 인물을 구분할 관리용 이름입니다. LLM에는 `Character 1` 같은 참조로 바꿔 전달하며 그대로 출력하지 않습니다.
- **이름 사용하지 않기**(기본): **이름 대신 사용할 지칭**에 `첫 번째 여성`, `왼쪽의 사람`, `우측 남성` 등을 한국어로 입력하면 LLM이 영문 묘사로 해석합니다. 비우면 `첫 번째 캐릭터`, `두 번째 캐릭터`가 기본이며 특징에 맞는 `첫 번째 여성` 등의 표현도 같은 인물을 가리키도록 전달합니다. 순번만으로 좌우 구도를 추가하지 않습니다.
- **이름 그대로 사용**: 출력할 이름·단부루 태그·LoRA 트리거를 직접 입력합니다. 해당 인물의 태그 구획에 입력 문자열을 보존합니다. CSV에 없는 사용자 지정 트리거도 유지하지만 CSV 검증 태그로 표시하지 않습니다. 학습 여부를 자동 추정해서 이름 사용을 켜지는 않습니다.
- 대체 지칭의 영어·한국어 표현은 Qwen이 작성하고 프로그램이 인물 ID로 묘사에 연결합니다. 지칭을 누락하거나 다른 ID에 연결한 응답은 오류로 표시하며, 이 검사는 번역 의미 자체의 정확성까지 보장하지는 않습니다.
- **배경**: 계속 유지할 장소·환경 등을 적습니다.
- **원하는 장면**: 이번 행동이나 바뀔 조건을 입력합니다. 새 요청이 이전 조건보다 우선합니다.
- **설정 저장**: 고정 컨텍스트를 디스크에 저장합니다. 생성·대화 전환·앱 종료 때도 자동 저장합니다.
- **이 대화의 기록**: 이전 결과를 다시 열어 복사할 수 있습니다. 최근 20회가 화면에 표시되며 저장 파일에는 전체 기록이 남습니다.

고정 컨텍스트는 매 요청에 포함합니다. 기본 로컬 모드의 최근 대화는 최대 **4회(user + assistant 쌍)**를 시간 순서로 보냅니다. 오래된 대화부터 입력 예산 밖으로 제외하며 화면에서 포함/제외 횟수를 확인할 수 있습니다. 고정 컨텍스트는 자동으로 잘라내지 않습니다. 고정 설정과 현재 요청만으로 예산을 넘으면 입력을 줄이도록 안내합니다.

**오래 유지할 수정은 고정 설정에 반영하세요.** 이전 대화를 자동으로 영구 설정으로 요약하거나 모델이 만든 특징을 자동 확정하지 않습니다. 예를 들어 여러 대화 뒤에도 빨간 머리를 유지하려면 캐릭터 설정을 수정해 저장합니다.

기본 로컬 모드에서 캐릭터 카드가 있는 대화는 과거 사용자 요청을 현재 캐릭터 설정으로 다시 해석합니다. 확장 모드에서는 이전 응답 포함 여부를 조절할 수 있습니다. 과거 생성문의 이름이나 음역이 되살아나지 않도록 이전 assistant 원문은 모델에 다시 보내지 않습니다. 저장된 원문과 화면의 대화 기록은 그대로 보존합니다. 기존 통합 캐릭터 설정은 내용을 유지한 한 장의 카드로 불러오며 필요하면 직접 여러 카드로 나누세요. 원래 `characters` 문자열도 저장 파일에 보존합니다.

모델 문맥 크기는 16,384토큰입니다. 입력 예산은 일반 모드 약 11,000토큰, 추론 모드 약 9,000토큰으로 제한하고 출력 공간을 남깁니다. UI 수치는 UTF-8 바이트 기반의 보수적 추정이며 모델 토크나이저의 정확한 측정값은 아닙니다.

## 기본 로컬 모드의 효율과 VRAM

- 기본: **LLM 1회 호출**, 추론 끔, 출력 태그 전체를 로컬 CSV와 대조.
- **생성 후 Qwen 메모리 해제**: 기본 켜짐. 생성 후 선택한 모델을 내립니다. 성공·실패 모두 해제를 시도하며 실패하면 알려줍니다.
- 메모리 해제를 끄면 **5분간 모델을 유지**해 연속 호출의 재로딩을 줄입니다. 컨텍스트 저장과 VRAM 유지 여부는 별개이므로 모델을 내려도 다음 요청에서 고정 설정과 최근 대화를 다시 전달합니다.
- **추론 모드**: 필요할 때 켜는 선택 옵션. 응답이 느려지거나 출력 길이 한도에 도달할 수 있습니다.
- **CSV 설명으로 추가 교정**: 관련 설명을 검색해 LLM을 한 번 더 호출합니다. 기본은 꺼짐.

선택 모델의 메모리 해제는 같은 모델을 공유하는 다른 앱에도 영향을 줍니다. 공유 중이면 해제를 끄세요. 다른 이름의 모델은 내리지 않습니다. 앱을 강제 종료했다면 필요시 `ollama stop qwen3:8b`로 해제할 수 있습니다.

## 저장과 출력

고정 설정과 전체 대화는 `state/sessions.json`에 저장됩니다. 임시 파일 작성 후 교체하는 방식으로 저장하며 앱을 다시 열어도 복원합니다. 저장 파일이 손상된 경우 빈 데이터로 덮어쓰지 않습니다. 이 폴더는 Git에서 제외됩니다. 브라우저에는 선택 모델 이름과 마지막 대화 ID만 저장합니다.

결과의 **생성용 복사**는 한국어 번역을 제외합니다. **전체 코드 블록 복사**는 요청한 단일 `text` 블록 형식입니다. **TXT 저장**은 전체 결과를 텍스트 파일로 저장합니다.

앱 화면은 loopback에서만 열리고 외부 CDN·폰트를 사용하지 않습니다. 기본 모드는 로컬 Ollama 모델만 사용합니다. Gemini 및 Ollama 확장 모드의 클라우드 모델은 선택한 컨텍스트를 외부 제공자에게 전송하며 화면에 전송 범위를 안내합니다. 키 저장과 데이터 이용 조건은 [확장 모드 안내](FRONTIER.md)를 확인하세요. 제공자 자체 로그 정책은 별개입니다.

## CSV 및 지침

`data/danbooru_tags_classified.csv`는 사용자가 준비하는 로컬 파일입니다. 개발 중 EasyUseAnima가 사용하는 CSV의 독립 사본으로 검증했으며, 해당 데이터는 재배포 조건을 확인하지 못해 Git에서 제외합니다. ComfyUI 실행이나 설치에 의존하지 않으며 원본을 변경하지 않습니다. 참조 출처와 형식은 `data/SOURCE.md`에 있습니다.

개발 검증에 사용한 사본은 114,092개 태그와 한국어 설명 71,179개를 포함합니다. 실제 파일은 4열과 5열(별칭 추가) 행이 섞여 있으며 앞의 태그명/분류/빈도/설명을 읽습니다. 일부 설명은 영어이거나 비어 있습니다. 실제 개수는 사용자가 선택한 CSV에 따라 달라집니다.

일반 태그는 CSV에 정확히 수록된 것만 출력합니다. 공백과 underscore는 동등하게 대조하고 출력은 소문자·공백을 사용합니다. 사용자가 이름 사용을 켜고 지정한 이름·LoRA 트리거는 예외로 원문을 유지하며 CSV 미확인 여부를 따로 표시합니다. 그 외 미확인 태그는 제외 사유를 표시합니다. CSV 미확인은 Danbooru 전체에 존재하지 않는다는 뜻이 아닙니다. **CSV 검증은 수록 여부를 확인하며 표현 품질·번역·장면 의미까지 보장하지는 않습니다.** 프롬프트 의미 조정은 별도 작업입니다.

`system_prompt.txt`를 수정하면 다음 생성부터 적용됩니다. 고정 컨텍스트 우선순위/입력 예산은 `sessions.py`, Ollama 호출과 검증은 `compiler.py`에 있습니다.

다른 CSV/포트: `python app.py --csv "path/to/tags.csv" --port 8766 --open`.
Ollama 주소 변경: `--ollama-url http://127.0.0.1:11434`. 로컬 HTTP 주소만 허용합니다.

## 검증

```powershell
python -m unittest discover -s tests -v
python -m py_compile app.py compiler.py sessions.py characters.py credentials.py gemini.py frontier.py ollama_frontier.py settings.py smoke_test.py
node --check web/app.js
python scripts/check_publication.py
```

자동 테스트는 자체 소형 fixture를 사용하므로 외부 CSV·Ollama·GPU 없이 실행할 수 있습니다. Node는 JavaScript 검사에만 필요하며 실행에는 필요하지 않습니다. `python smoke_test.py`는 CSV와 실행 중인 Ollama가 필요한 선택 검증입니다. 고정 설정과 2회 대화 전달, 디스크 복원, 모델 유지/해제를 검사하고 `runtime-validation.json`에 합성 예시 결과를 기록합니다. 출력 파일은 Git에서 제외하며 표현 품질 자동 평가가 아닙니다.
